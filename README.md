# 英会話練習アプリ

録音した音声を PC 内で分析する Gradio アプリです。分離モードは外部アプリと会話し、このアプリでは自分のマイクだけを録音します。ローカルモードは Ollama と Piper を使います。画面は `127.0.0.1` だけで開き、公開リンクは作りません。

## 起動

PowerShell でこのフォルダに移動し、以下を順に実行します。

```powershell
.\run.ps1 sync
.\run.ps1 doctor
.\run.ps1 models
.\run.ps1 app
```

コード側の自動テストは `.\run.ps1 test` で実行できます。

## 会話モデルを選ぶ

「設定」タブで候補を選ぶと、説明・容量・導入コマンドが切り替わります。「この PC の導入状況を確認」で、Ollama とモデルの保存状態を確認できます。候補の選択だけではダウンロードや設定保存は行いません。

| モデル名 | ダウンロードの目安 | 試す場面 |
| --- | --- | --- |
| `llama3.2:3b` | 約 2.0 GB | まず英語の対話を試す候補 |
| `qwen2.5:3b` | 約 1.9 GB | 日本語の指示も試したい場合 |
| `gemma3:4b` | 約 3.3 GB | Google の多言語モデルを試す場合 |
| `llama3.2:1b` | 約 1.3 GB | 小さいモデルから試したい場合 |

`llama3.2` は種類・バージョン、`3b` は約30億パラメータを表します。容量は実行時のメモリ量とは異なります。速度と訂正精度はこのアプリでは未測定です。初回は短い会話で確かめてください。容量・対応言語・ライセンスの情報は2026-09-30に [Llama 3.2](https://ollama.com/library/llama3.2)、[Qwen 2.5](https://ollama.com/library/qwen2.5)、[Gemma 3](https://ollama.com/library/gemma3) の公式配布ページで確認しています。

たとえば最初の候補を導入するには、Ollama のインストール後に PowerShell で `ollama pull llama3.2:3b` を実行します。導入後に同じ名前を選んで「設定を保存」してください。保存済みモデルは `ollama list` でも確認できます。

### 「ollama が認識されません」と出る場合

モデルの導入前に、[Ollama の Windows 版](https://ollama.com/download/windows) 本体をインストールしてください。その後、PowerShell を閉じて開き直します。通常のインストール先であれば、以下のように場所を直接指定することもできます。

```powershell
& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" pull llama3.2:3b
```

アプリの「この PC の導入状況を確認」は、Ollama 本体が見つからない場合と、導入済みで起動していない場合を区別して表示します。

`prepare_models.py` は初回だけネット接続を使って Whisper、音素認識、distilgpt2 の重みを保存します。録音や文字起こしをアップロードしません。通常の `app.py` はモデルをローカルキャッシュからだけ読みます。モデルが足りない段階は `analysis.json` の `stage_errors` とレポートに表示します。

追加で Java が必要です。`models` コマンドは Piper の英語音声モデルも保存します。ローカル会話を使う場合は [Ollama の Windows 版](https://ollama.com/download/windows) とダウンロード済みのローカルモデルが必要です。モデル名を設定タブで入力してください。録音・文字起こしを外へ出さないため、Ollama の `%USERPROFILE%\.ollama\server.json` に `{"disable_ollama_cloud": true}` を設定してから Ollama を再起動してください。既存の設定がある場合は項目を追加します。アプリはクラウドを無効化した設定とローカルモデルを確認できるまで会話を始めません。espeak-ng の DLL は `espeakng-loader` で指定します。Windows でマイクを他アプリと併用できない場合は、サウンド設定の排他モードを確認してください。

## 使い方

1. まず分離タブで録音します。外部アプリとの会話ではヘッドホンを使ってください。
2. 停止後に分析が始まり、HTML と JSON が `data/sessions/` に残ります。停止時に保存した録音は分析が失敗しても残ります。録音中の音声はメモリ上だけに置くため、停止前にアプリを閉じるとその回の録音は破棄されます。
3. ローカルタブでは場面と練習モードを選びます。話し終わりは「ローカル会話で話し終わりとみなす無音」（既定1.2秒）で判定します。講師モードは1ターンに最大1件を訂正し、言い直しは最大2回です。同じ分類は3ターン続けて指摘しません（設定で変更可）。相手の声が流れている間のマイク音声は、自分の発話として扱いません。
4. 履歴タブから保存済み録音を再分析できます。設定変更後も元の録音は保持します。

## English Express

`English-Express-with-import.html` は既存の `C:\effort\pron-coach\english-express.html` を読み取り、右下の「英会話カードを取り込む」を加えたコピーです。元ファイルは変更していません。レポートタブの「English Express に書き出す」で、表示中のレポートの指摘を1件につき1枚のカードにします（表 `ja`：日本語の注意点、裏 `en`・`ex`：正しい英文、`exJa`：IPA）。`topic` は `英会話/分類コード/セッションID` です。カードは既存の `en`・`ja`・`ex`・`exJa`・`topic` 形式で、ローカルの学習カード保存先に追加されます。元ファイルが更新されたら、次のコマンドでコピーを作り直せます。

```powershell
uv run integrate_english_express.py C:\effort\pron-coach\english-express.html
```

## 状態と限界

- 自動テスト（`.\run.ps1 test`）、ローカル HTTP 応答、モデル重みの読み込み、Piper の音声生成、合成音声による録音後の分析を確認済みです。実際に人が話した15分録音と、Ollama を含むローカル会話の通し検証は未完了です。
- 発音の音素時刻と単語時刻を重ねる方法は推定です。各音素は中心の時刻を含む単語に1回だけ割り当てます。語末の母音挿入（EPENTHESIS）は、子音で終わる単語の最後の音素より後ろに母音が入った場合だけです。確信度が低い箇所は判定から外しますが、正誤を保証しません。舌の実際の位置は音声から分かりません。
- 言い間違い候補は、wordfreq の頻出語（既定3万語）を espeak の IPA で引ける辞書にし、分類表の置換を1つだけ施した音素列に一致する実在語を探します。distilgpt2 の対数尤度差が閾値以上の場合だけ候補にし、文脈上の意図は確定しません。
- ノイズ除去は任意です。設定でオンにすると DeepFilterNet を使いますが、依存関係には含めていません（numpy などの版と衝突する可能性があるため）。未導入のままオンにした場合は、元の音声で分析し「判定できなかった項目」に理由を表示します。
- 講師モードは開始時に判定用モデルを先読みしますが、応答時間の目標（訂正の読み上げまで5秒）と判定精度は実測していません。
- 仕様書の合格基準には本人が録音した `tests/audio/` が必要です。`uv run evaluate_audio.py` で最小対の検出率・誤検出率を計算できます。現時点では音声セットがなく、精度と5分の通しテストは未評価です。
- この画面は一人で使うローカル実行を前提としています。同時に複数のブラウザから録音を操作しないでください。
- 仕様書の `pipeline/` フォルダ分割は行わず、9段階の処理は `engine.py` にまとめています。

## 保存とプライバシー

`data/` と `exports/` は `.gitignore` に入れています。分離モードで貼り付けた会話履歴も `data/` 内です。`Claude に貼る用テキスト` は手動コピー用で、Claude API も画面の自動操作も使いません。録音内容は Ollama にも送らず、ローカル会話では文字起こしテキストだけを `127.0.0.1:11434` に渡します。
